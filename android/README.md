# Cloud Music

Нативный Android-плеер для музыкальной коллекции в публичной папке Яндекс Диска или Google Drive. Минималистичный интерфейс с тёмными поверхностями и зелёным акцентом в духе Spotify; тёмная и светлая темы.

## Возможности

- Вставка ссылки на папку и определение сервиса без ручного выбора.
- Список файлов из подпапок; постраничное чтение Яндекс Диска.
- Поиск по треку, исполнителю и альбому; сортировка по названию или исполнителю.
- Вкладка исполнителей: поиск, отдельный список треков и очередь только выбранного исполнителя.
- Раздел «Папки» → «На устройстве»: добавление уже скачанных файлов и папок через системный выбор, без копирования; локальное воспроизведение без интернета.
- Избранное, альбомы, несколько источников и обновление папок.
- Мини-плеер и полный плеер: перемотка, предыдущий/следующий трек, повтор, случайный порядок, очередь.
- Media3 MediaLibraryService: воспроизведение в фоне, уведомление и системные медиакнопки; обработка аудиофокуса и отключения наушников.
- Локальное сохранение библиотеки, избранного и темы.
- Обложки MP3/FLAC в списке: чтение встроенного изображения без скачивания всего трека, кэш на устройстве.
- Явное скачивание треков Яндекс Диска через меню трека: прогресс, очередь, ожидание сети, отмена, повтор и удаление отдельной копии. Файлы сохраняются в `Downloads/Cloud Music`, доступны офлайн и после перезапуска.
- Скачанные копии автоматически используются при запуске исходного облачного трека. В общей медиатеке не появляются дубли; после отключения облачной папки скачанные файлы остаются доступны.
- Адаптивная иконка Android с тёмным фоном, без белого поля вокруг маленького логотипа. Поддерживается монохромная тема лаунчера Android 13+.
- Аудио не записывается на диск автоматически; убран отдельный фоновый прогрев соседних треков. Старый аудиокэш удаляется при обновлении.
- Кэш обложек до 4 МиБ на диске и 4 МиБ bitmap в RAM; очистка в настройках.
- Уже прочитанные заголовки файлов повторно используются в RAM: до 1 МиБ всего, 256 КиБ на запись.
- Потоковый буфер в RAM с целевым пределом 4 МиБ: старт от 250 мс, запас для восстановления после остановки 8 секунд; фактическое время зависит от сети, формата и облака.
- Короткое смещение экрана через графический слой, появление обложек и индикатор играющего трека. Нет двойной отрисовки страниц, растягивания мини-плеера или покадровой интерполяции всей темы.
- Полный плеер распределяет пространство по высоте экрана; снизу карточка «Далее» и очередь. На небольшом экране доступна прокрутка.
- Приём ссылки через Android «Поделиться».
- Android Auto: медиатека, исполнители, папки и избранное, поиск и запуск через медиасессию. «На устройстве» находится внутри папок. Выбор трека формирует очередь соответствующего раздела.
- Chromecast: кнопка трансляции, выбор устройства, управление воспроизведением и возврат на телефон из полного плеера. SDK подключается при первом обращении к трансляции.

Скачивание запускает только пользователь. Сохранённые файлы занимают место в хранилище; размер виден в меню и списке загрузок. Системный DownloadManager продолжает загрузку в фоне, при потере сети может ожидать подключения. Для повторной попытки истёкшая ссылка обновляется. Загрузки по мобильной сети разрешены, в роуминге — нет.

Для облачных треков нужен интернет; ссылка должна разрешать просмотр и скачивание. Медленная сеть ниже битрейта исходного файла не может обеспечивать непрерывное воспроизведение бесконечно: сервер диска не перекодирует треки для этого приложения. Буфер помогает переживать краткие провалы. Для автономного прослушивания добавьте файлы устройства в «Папках» или скачайте выбранные треки через меню.

## Источники

Яндекс Диск: REST API публичных ресурсов, пагинация и подпапки. Используются прямые `file`-ссылки из списка ресурсов, если они доступны; иначе запрашивается ссылка скачивания. Временные ссылки повторно используются до четырёх минут в памяти и закрытой базе приложения (не более 512 записей до 4096 символов). При HTTP 401/403/410/500/502/503/504 ссылка обновляется один раз. Просроченные записи удаляются; версия папки предотвращает использование старых ссылок после обновления коллекции. Автоматического аудиокэша нет; пользователь может сохранить выбранные треки через DownloadManager.

Google Drive: публичное представление `embeddedfolderview`, включая подпапки и `resourcekey`; публичная загрузка файла с обработкой формы подтверждения больших файлов. Используется веб-интерфейс Google, структура которого может измениться. Вход в Google, закрытые папки и обход ограничений скачивания не реализованы. Поддержку Google нельзя считать проверенной для каждой папки только по успешному разбору HTML.

Для облачных файлов название и исполнитель определяются из имени файла `Исполнитель - Название.ext`; альбом — из папки. Без такого имени показывается «Неизвестный исполнитель». Встроенные обложки MP3 (ID3v2.2/2.3/2.4) и FLAC читаются для видимых треков, один фоновый запрос одновременно. Читается максимум 4 МиБ метаданных; уже прочитанный заголовок повторно используется из RAM, отдельного прогрева аудио нет. Буферизация облачной музыки имеет приоритет перед фоновыми запросами до накопления 20 секунд запаса. Локальная музыка и полностью полученный поток не блокируют обложки. Media3 может буферизовать ближайший участок очереди в пределах общего RAM-буфера для непрерывного перехода. Изображения уменьшаются до 384 пикселей для кэша. Для других форматов обложка может появиться после извлечения Media3 во время воспроизведения. При отсутствии изображения используется собственная геометрическая обложка. Внешние музыкальные каталоги не используются.

Локальные файлы открываются по `content://` URI с сохраняемым разрешением чтения, без копирования. Папка сканируется вместе с подпапками; метаданные берутся из файла с запасным разбором имени. Если оригинал удалён или разрешение отозвано, файл нужно выбрать снова.

Для сохранения в общую папку на Android 8–9 приложение запросит разрешение записи в хранилище. На Android 10+ широкое разрешение не запрашивается. Скачанные файлы не удаляются при отключении исходной папки; отдельная команда «Удалить скачанную копию» удаляет только выбранную загрузку приложения.

Папки и избранное хранятся в закрытой SQLite-базе приложения; тема — в SharedPreferences. Удаление источника отключает его в приложении и не изменяет файлы на диске. Собственная аналитика и удалённый сервер приложения отсутствуют. При работе с музыкой устройство обращается к серверам выбранного облака. Для Chromecast добавлен Google Cast SDK / Google Play services; обработку данных этих компонентов необходимо учитывать отдельно при заполнении деклараций магазина.

## Android Auto и Chromecast

Android Auto использует стандартный интерфейс автомобильного хоста и медиасессию Cloud Music. Доступ разрешён собственному приложению, контроллерам с той же подписью, доверенным системным контроллерам и Google-подписанному Android Auto. Голосовой запуск поддерживает MEDIA_PLAY_FROM_SEARCH; фактическое распознавание зависит от установленного ассистента и автомобильного хоста.

Для Chromecast нужны Google Play services, совместимый приёмник и общая Wi-Fi сеть. VPN должен разрешать доступ к локальной сети. Встроенный Default Media Receiver не требует отдельного ключа API или регистрации receiver-приложения. Телефон остаётся источником потока: на время сессии открывается локальный HTTP-канал с непредсказуемым токеном, поддержкой диапазонов и ограниченными буферами. Через него передаются как облачные треки, так и выбранные локальные файлы; автоматических копий аудио на диске нет. Телефон должен оставаться в сети и включённым. Доступны форматы, поддерживаемые приёмником; локальный провайдер должен сообщать размер и разрешать чтение файла.

Очередь хранится на телефоне, приёмнику передаётся текущий трек. Поддерживаются следующий/предыдущий, перемотка, повтор и случайный порядок. Кнопка «На телефон» переносит воспроизведение обратно; неожиданное отключение приёмника оставляет телефон на паузе. Локальный канал закрывается после завершения сессии. Обложки для внешних устройств предоставляются из уже готового ограниченного кэша.

Проверены каталог, поиск, очереди, фоновый запуск, локальная HTTP-передача реального файла Яндекс Диска и SAF-файла, а также поведение при недоступных Play services. Реальная машина и Chromecast к рабочей среде не подключены: обнаружение приёмника и воспроизведение на нём требуют отдельной проверки на оборудовании.

## Сборка

Требования: JDK 17, Android SDK 36, Build Tools 35.0.0 (AGP 8.10.1). Укажите SDK в `local.properties`:

```properties
sdk.dir=/absolute/path/to/Android/sdk
```

Пользовательская версия **0.4.0** собирается как `release`: отладка выключена, R8 удаляет неиспользуемый код и обфусцирует оставшийся, ресурсы сокращаются. APK подписан отдельным постоянным ключом Cloud Music.

Для повторной подписанной сборки создайте локальный `signing.properties` по образцу `signing.properties.example` либо укажите путь к приватному файлу переменной `CLOUD_MUSIC_SIGNING_PROPERTIES`. Ключ и пароли не входят в исходный архив. Без локальной конфигурации Gradle создаст неподписанный release APK.

```sh
./gradlew :app:assembleRelease :app:bundleRelease :app:testReleaseUnitTest :app:lintRelease
```

Для Google Play подготовлен AAB версии 0.4.0 с targetSdk 36 / Android 16 и прежней release-подписью Cloud Music. Устаревший AAB 0.3.1 использовал targetSdk 35. Загрузка в Play Console и публикация отдельно не выполнялись.

APK для прямой установки: `app/build/outputs/apk/release/app-release.apk`. AAB для загрузки в магазин: `app/build/outputs/bundle/release/app-release.aab`; AAB не устанавливается нажатием на файл. Публикация в магазине отдельно не выполнялась.

Приложение: `app.cloudmusic`, версия `0.4.0` (versionCode 7), Android 8.0+ (minSdk 26), targetSdk 36.

### Переход с прежних тестовых APK

Версии до 0.3.0 включительно подписывались Android Debug. Android не разрешает обновить их APK с новым release-ключом. Сначала сохраните ссылки на папки и учтите, что удаление debug-приложения удалит его библиотеку, избранное, настройки и разрешения доступа к локальным папкам. После удаления установите release APK и подключите папки заново. Оригинальные файлы в облаке и выбранные файлы устройства приложение при удалении не стирает. Заранее сохранённые в общей папке `Downloads/Cloud Music` файлы можно добавить заново через «Папки» → «На устройстве»; их старый внутренний индекс загрузок не переносится.

Последующие release-обновления должны подписываться тем же ключом и иметь больший versionCode, тогда они устанавливаются поверх с сохранением данных. Приватный ключ необходимо хранить отдельно от APK и исходного архива.

Для разработки по-прежнему доступна тестовая сборка:

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

## Проверка на устройстве

```sh
./gradlew :app:connectedDebugAndroidTest
```

Для проверки готового release APK через системный интерфейс используется отдельный процесс `release-qa`; он не подключает классы приложения и не меняет правила оптимизации APK. Инструкция — в `release-qa/README.md`.

По умолчанию сетевой тест реальной папки пропускается. Чтобы проверить собственную публичную папку, передайте параметры инструментальным тестам:

```sh
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.yandex_folder='https://disk.yandex.ru/d/EXAMPLE' \
  -Pandroid.testInstrumentationRunnerArguments.expected_tracks=256
```

Дополнительные проверки покрывают скачивание через системный DownloadManager, защиту от дубликатов, отмену без прерывания проигрывания, офлайн-запуск оригинального трека через локальную копию, сохранение после отключения источника, удаление копии, адаптивную иконку, а также миграцию базы с сохранением избранного, диапазоны при повторном использовании заголовка, медленный поток и краткий провал сети, локальную папку и воспроизведение при отключённых сетях. Тест локальной папки ожидает два оригинальных WAV-файла `QA Artist - First.wav` и `QA Artist - Second.wav` в `Download/CloudMusicQA` тестового устройства.

Тест открывает поток, проверяет воспроизведение после Home и перемотку. Он не изменяет файлы в облаке. Демо-коллекция состоит из трёх оригинальных синтезированных звуковых фрагментов и явно подписана как локальная.

## Технологии и документы

Kotlin, Jetpack Compose, Media3/ExoPlayer, OkHttp, Jsoup, SQLite. Зависимости закреплены в `app/build.gradle.kts`.

- [Media3: фоновое воспроизведение](https://developer.android.com/media/media3/session/background-playback).
- [Google Drive: resource keys](https://developers.google.com/workspace/drive/api/guides/resource-keys).
- [Google Drive: скачивание файлов](https://developers.google.com/workspace/drive/api/guides/manage-downloads).
- [gdown: описание подхода к публичным папкам](https://github.com/wkentaro/gdown). Реализация клиента в проекте написана на Kotlin; исходный код gdown не включён.
